# 위협 모델과 개인정보 처리 원칙

## 1. 보호 대상

| 자산 | 민감도 | 위치 |
|---|---|---|
| LMS 세션 쿠키(`MoodleSession*`), `sesskey`, (있다면) 웹서비스 토큰 | 매우 높음 — 탈취 시 학생 계정으로 LMS 전체 열람 가능 | `%LOCALAPPDATA%\jbnu-lms-mcp\session.dpapi` (DPAPI 암호화) |
| 로그인용 브라우저 프로필(SSO 쿠키 포함) | 매우 높음 | `%LOCALAPPDATA%\jbnu-lms-mcp\browser-profile\` (Chrome/Edge 자체 암호화) |
| 강좌·과제·공지 메타데이터 스냅샷 | 중간 — 개인 학습 정보 | `%LOCALAPPDATA%\jbnu-lms-mcp\state\snapshot.json` (평문 JSON, 제목·마감만) |
| 다운로드한 수업자료 | 중간~높음 — 저작물 | `~/Downloads/jbnu-lms/` |
| 통합인증 아이디·비밀번호·패스키·OTP | 최고 | **이 프로그램은 취급하지 않음** |

## 2. 신뢰 경계

```
사용자 ──(브라우저, 직접 인증)──▶ sso.jbnu.ac.kr ──▶ lms.jbnu.ac.kr
   │                                                   ▲
   │ MCP 클라이언트(Claude Desktop/Codex) ── STDIO ──▶ jbnu-lms-mcp ──HTTP(쿠키)──┘
   │                                                   │
   └── 로컬 디스크(DPAPI 파일, 브라우저 프로필, 스냅샷) ◀┘
```

- MCP 서버는 로컬 STDIO 로만 동작하며 네트워크 포트를 열지 않는다.
- LMS 호스트(`lms.jbnu.ac.kr`) 외의 어떤 호스트에도 쿠키·토큰을 보내지 않는다(`http/client.ts` 의 호스트 고정). 외부로의 리다이렉트는 따라가지 않는다.
- SSO 호스트에는 자동화를 붙이지 않는다. 세션 검증용 headless 브라우저는 LMS 호스트 외 요청을 전부 차단한다.

## 3. 위협과 통제

| # | 위협 | 통제 | 잔여 위험 |
|---|---|---|---|
| T1 | 세션 파일 탈취(다른 사용자·악성코드) | DPAPI CurrentUser 범위 암호화(같은 Windows 계정에서만 복호화), 파일 권한 0600 시도 | 같은 계정에서 실행되는 악성코드는 복호화 가능 |
| T2 | 로그·응답을 통한 유출 | 로거가 쿠키·토큰·sesskey·32자 hex·비밀번호 패턴을 마스킹, 본문(description/body) 필드 차단, stdout 은 MCP 채널 전용 | 새 패턴 누락 가능 → `tests/security` 로 회귀 방지 |
| T3 | AI 대화에 비밀값 노출 | 도구 응답에 자격 증명을 넣지 않음. `get_auth_status` 는 저장 위치·방식만 표시 | 없음(테스트로 확인) |
| T4 | 피싱성 외부 링크로 쿠키 전송 | 호스트 고정, 외부 리다이렉트 중단 | 없음 |
| T5 | LMS 본문에 포함된 프롬프트 주입 | 응답에서 원문과 추정을 구분 표기, 본문은 "원문" 블록으로 인용, 상태 변경 도구 없음 | AI 가 원문 지시를 따를 가능성은 클라이언트 측 통제에 의존 |
| T6 | 과도한 요청으로 인한 LMS 부하·차단 | 동시 3건, 요청 간 250ms, 지수 백오프 재시도 2회, 60초~5분 캐시 | 대량 강좌 조회 시 시간이 걸릴 뿐 |
| T7 | Git 에 비밀값 커밋 | `.gitignore`(dpapi, profile, session), `scripts/check-secrets.mjs`, 보안 테스트 | 개발자가 강제로 추가하는 경우 |
| T8 | 브라우저 프로필에 비밀번호 저장 | 프로필 생성 시 비밀번호 관리자·자동완성·동기화 비활성 Preferences 기록 | 사용자가 설정을 다시 켜는 경우 |
| T9 | keep-alive 로 세션이 장시간 유지 | `JBNU_LMS_KEEPALIVE=0` 으로 끌 수 있음, 서버 종료 시 중단 | PC 잠금 없이 자리 비움 |
| T10 | assisted 로그인 창이 SSO 에 노출 | SSO 페이지 내용은 읽지 않음, URL 호스트만 확인 | 학교 정책상 자동화 브라우저 사용을 제한할 수 있음 → plain 모드 제공 |
| T11 | 상태 변경(제출·게시·삭제) 오작동 | 그런 기능이 코드에 없음(읽기 전용) | 없음 |

## 4. 개인정보 처리 원칙

1. **최소 수집**: 표시 이름과 사용자 ID 외의 프로필 정보는 저장하지 않는다. 학번은 저장·로그하지 않는다.
2. **로컬 보관**: 모든 데이터는 사용자 PC 를 떠나지 않는다. 텔레메트리·외부 전송 없음.
3. **삭제권**: `disconnect_lms`(또는 `jbnu-lms-mcp logout --delete-profile --delete-snapshot`)로 세션·프로필·스냅샷을 즉시 삭제할 수 있다.
4. **투명성**: 모든 응답에 데이터 출처(공식 API/AJAX/화면 해석/AI 추정)와 원문 URL 을 표시한다.
5. **저작물 존중**: 수업자료는 사용자가 명시적으로 요청할 때만 다운로드하며 자동 수집하지 않는다. 자료의 재배포는 학교 규정을 따른다.
6. **테스트 데이터**: 테스트는 익명화된 fixture 와 로컬 mock 서버만 사용한다. 실제 학생 데이터는 저장소에 넣지 않는다.

## 5. 사용자가 알아야 할 사항

- 이 도구를 설치한 PC 에 로그인할 수 있는 사람은 저장된 LMS 세션을 쓸 수 있다. 공용 PC 에서는 사용을 마친 뒤 반드시 `disconnect_lms` 를 실행하라.
- LMS 세션은 보통 8시간 유휴 후 만료된다. keep-alive 를 켜 두면 MCP 서버가 살아 있는 동안 계속 연장된다.
- 통합인증 화면에 나타나는 어떤 정보도 이 도구는 읽지 않는다. 비밀번호·인증 코드를 채팅에 입력하지 마라.
