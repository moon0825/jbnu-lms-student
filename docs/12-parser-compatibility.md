# LMS 화면 변경 대응 설계

버전 0.6.0 · 2026-09-04

## 목표

LMS의 CSS 클래스나 테마가 소폭 바뀌어도 공지·과제·수업자료 조회가 바로 중단되지 않게 한다. 반대로 전혀 모르는 화면을 `0건`으로 오인해 학생에게 잘못 안내하지 않는다.

## 3단계 파싱 정책

1. **알려진 레이아웃 프로필**: Moodle 표준, Coursemos 현재형, 레거시 구조의 선택자를 함께 지원한다.
2. **의미 기반 폴백**: CSS 대신 `/course/view.php?id=`, `/mod/.../view.php?id=`, `article.php?bwid=` 같은 안정적인 URL과 `time`, `data-label`, `dt/dd` 의미를 사용한다.
3. **안전한 실패**: 알려진 빈 화면 문구도, 의미 링크도 찾지 못하면 `PARSE` 오류로 중단한다. 알 수 없는 화면을 빈 목록으로 반환하지 않는다.

각 파서는 `ParserCompatibility`를 반환한다.

| 필드 | 용도 |
|---|---|
| `contractVersion` | 파서 진단 계약 버전 |
| `layout` | 일치한 비식별 레이아웃 프로필 |
| `confidence` | `high` 또는 `fallback` |
| `warnings` | 구조 변경 후보에 대한 고정 문구 |

어댑터는 `fallback` 사용 시 HTML, 강좌명, 사용자명, URL을 기록하지 않고 파서명·계약 버전·레이아웃만 경고 로그에 남긴다.

## 확장 방법

LMS 구조가 바뀌면 다음 순서로 대응한다.

1. 실제 페이지를 저장하지 말고 개인정보를 제거한 최소 HTML fixture를 만든다.
2. `tests/unit/parsers.test.ts`에 실패 재현 테스트를 먼저 추가한다.
3. 기존 의미 기반 폴백으로 해결 가능한지 확인한다.
4. 불가능할 때만 해당 파서에 새 레이아웃 프로필을 추가한다.
5. 기존 fixture와 새 fixture를 모두 통과시킨다.
6. `npm run check:secrets`로 fixture에 이름·이메일·전화번호·세션이 없는지 확인한다.

## 지원 경계

- URL과 HTML 구조가 모두 바뀌면 파서 업데이트가 필요하다.
- JavaScript 실행 후에만 보이는 데이터는 Moodle AJAX/API 어댑터를 우선 사용한다.
- 로그인, 권한 거부, 점검 화면은 콘텐츠 파서로 억지 해석하지 않는다.
- 파서 폴백은 읽기 전용 조회에만 사용하며 제출·수정 동작을 추론하지 않는다.
