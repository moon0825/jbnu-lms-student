# 요구사항 분석서

버전 0.1.0 · 2026-09-04

## 1. 목표

전북대학교 LMS(JBNU LXP, Moodle 4.5 + Coursemos)에 로그인한 학생이 AI 클라이언트(Claude Desktop, Codex 등)에서 자연어로
공지·과제·마감·수업자료를 조회하고 "오늘/이번 주 해야 할 일"을 정리받을 수 있는 **Windows 로컬 STDIO MCP 서버**를 만든다.
학생 개인정보와 학습자료 보호를 위해 모든 처리는 사용자 PC 안에서 끝나야 한다.

## 2. 이해관계자와 페르소나

- **학생(주 사용자)**: 여러 강좌를 수강하며 공지·과제 누락을 걱정한다. 기술 지식은 다양하므로 설치는 스크립트 한 번, 로그인은 평소 쓰던 브라우저 방식이어야 한다.
- **학교/LMS 운영자**: 과도한 요청·자동화 로그인을 원하지 않는다. 읽기 전용, 속도 제한, 인증 절차 존중이 필요하다.
- **개발자/유지보수자**: LMS 화면이 바뀌어도 파서만 고치면 되도록 계층이 분리되어야 한다.

## 6. 범위 밖

- 과제 제출, 게시글 작성, 메시지 전송, 출석 체크 등 상태 변경
- 성적 조회(권한과 개인정보 민감도가 높아 1차 범위에서 제외; 로드맵 참고)
- 전북대 포털 공지·학사 일정·JUIC 연구정보 (별도 어댑터로 확장 예정, 로드맵 참고)

## 7. 제약과 가정

- 학생은 공식 Moodle 토큰을 발급받을 수 없다(ADR-001). 따라서 세션 방식이 기본이다.
- LMS 세션은 유휴 8시간(`sessiontimeout=28800`) 후 만료된다. keep-alive 로 서버 실행 중에는 연장한다.
- Coursemos 전용 화면(ubboard, 강좌 메뉴)은 공개 마크업(다른 대학 Coursemos 사이트)을 참고해 파서를 만들었고, 실제 전북대 화면에서 검증한 결과는 `docs/09-live-verification.md` 에 기록한다.
