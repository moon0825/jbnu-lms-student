# 오류·복구 UX 계약

버전 0.6.0 · 2026-09-04

## 목표

사용자는 오류 원문을 해석하지 않아도 다음 네 가지를 즉시 알아야 한다.

1. 하던 작업 중 무엇이 실패했는가
2. LMS 원본과 로컬 파일에 어떤 영향이 있는가
3. 서버가 이미 자동 복구를 시도했는가
4. 지금 실행할 수 있는 가장 안전한 다음 행동은 무엇인가

모든 도구는 조회 전용이므로 실패 응답은 LMS 원본 데이터가 바뀌지 않았음을 명시한다. 비밀번호, 패스키, OTP, 쿠키, 토큰, 게시글 본문은 진단 ID나 오류 로그에 포함하지 않는다.

## 실패 응답 계약

완전 실패는 MCP `isError: true`로 반환한다. 사람에게 보이는 `content[0].text`에는 제목, 설명, 요청 작업, 영향 범위, 자동 복구, 해결 방법, 다음 행동, 진단 ID가 들어간다.

`structuredContent.error`는 다음 필드를 고정적으로 제공한다.

| 필드 | 의미 |
|---|---|
| `kind` | 클라이언트 분기용 안정적 오류 종류 |
| `severity` | `warning` 또는 `error` |
| `title`, `message`, `hint` | 한국어 설명과 해결 방법 |
| `operation` | 실패한 사용자 작업명 |
| `impact` | 완료되지 않은 범위와 데이터 변경 여부 |
| `automaticRecovery` | 제한 재시도·세션 재검증 여부 |
| `retryable` | 같은 입력으로 재시도 가능한지 |
| `retryAfterSeconds` | 서버 권장 대기 시간, 없으면 `null` |
| `recoveryAction` | 복구 행동 종류, 표시명, 실행 가능한 MCP 도구와 인자 |
| `reportAction` | 진단 ID와 관련 도구가 미리 연결된 `report_lms_problem` 안내 |
| `diagnosticId` | `JBNU-YYYYMMDD-XXXXXX` 형식의 비식별 지원 번호 |
| `occurredAt` | UTC ISO 8601 발생 시각 |

진단 ID는 오류 인스턴스를 서로 구분하기 위한 값일 뿐 사용자 계정, 강좌, URL 또는 인증정보를 인코딩하지 않는다.

## 복구 정책

| 상황 | 자동 처리 | 사용자에게 제시할 행동 |
|---|---|---|
| 세션 없음·만료 | 가능한 경우 세션을 재검증하고 원 요청을 1회 재실행 | `connect_lms` |
| 로그인 진행 중·브라우저 사용 중 | 중복 로그인 창을 열지 않음 | `get_auth_status(verify=true)` |
| 429 속도 제한 | 지수 백오프와 `Retry-After` 중 큰 값 사용, 호출당 최대 10초 대기 | 남은 권장 시간 뒤 재시도 |
| 503 점검·일시 중단 | 제한 횟수 재시도 | LMS 웹 상태 확인 후 재시도 |
| 네트워크·타임아웃·5xx | 제한 횟수 지수 백오프 재시도 | 네트워크/LMS 확인 후 재시도 |
| 접근 거부·화면 변경 | 무한 재시도 금지 | LMS 원문 확인 |
| 디스크 부족·권한 오류 | 파일 쓰기 반복 금지 | 공간 확보, 경로 또는 권한 변경 |
| 200MB 초과 다운로드 | 로컬 저장 중단 | LMS 브라우저에서 직접 다운로드 |

`Retry-After`가 하루를 넘으면 사용자 안내값은 86,400초로 제한한다. 한 MCP 호출이 장시간 멈추지 않도록 실제 자동 대기는 최대 10초지만, 서버가 제시한 전체 권장 시간은 오류 응답에 보존한다.

다운로드는 최종 경로와 같은 폴더의 무작위 `.partial` 파일에 먼저 기록하고 성공한 경우에만 이름을 바꾼다. 쓰기나 이름 변경이 실패하면 임시 파일을 정리한다. 사용자가 지정하는 `target_dir`은 상대 경로 해석 차이를 막기 위해 절대 경로만 허용한다.

## 부분 실패와 빈 결과

여러 강좌를 모아 조회할 때 한 강좌만 실패하면 전체 요청을 실패시키지 않는다. 확인된 결과를 반환하고 `notes[]`에 다음 정보를 넣는다.

- `code`: 원인 종류
- `scope`: 영향을 받은 강좌 또는 기능
- `retryable`: 같은 요청을 다시 시도할 수 있는지
- `recoveryAction`: 권장 복구 행동

항목이 0건이고 경고가 없다면 `✅`와 함께 확인된 빈 결과로 표시한다. 항목이 0건인데 경고가 있으면 `⚠️ 확인된 항목은 0건이지만 ... 전체 결과가 아닐 수 있습니다`로 표시한다. 따라서 사용자는 “정말 없음”과 “일부를 못 읽음”을 구분할 수 있다.

## 운영·지원 규칙

- 사용자가 제보할 최소 정보는 진단 ID, 실패한 도구명, 발생 시각이다.
- 디버그 로그 공유 전에도 쿠키·토큰·비밀번호·세션 키가 없는지 확인한다.
- 진단 ID만으로 인증정보를 복구하거나 LMS 계정을 식별할 수 없어야 한다.
- 새 오류 종류를 추가할 때 사용자 문구, 복구 행동, 단위 테스트, 도구 명세를 함께 갱신한다.
